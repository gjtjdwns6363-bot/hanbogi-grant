# 정부 지원금 찾기 (grant.hanbogi.com)

보조금24 공공서비스 자료로 매일 05:30 KST에 다시 만드는 정적 사이트. GitHub Actions(`.github/workflows/build.yml`)가 `node build.js`로 `dist/`를 만들어 GitHub Pages에 배포한다. 생성물은 커밋하지 않는다.

- `node build.js` — 실제 API 호출 (env `DATA_GO_KR_KEY` = 공공데이터포털 **디코딩** 키, 저장소 시크릿)
- `node build.js --fixtures` — `fixtures/`의 샘플 응답으로 생성 (키 불필요)
- `node test.js` — 신청기한 파싱·지역 매핑·대상 분류(부정 가드 포함)·랜딩 noindex·색인 기준·사이트맵 분할 검사

인증 실패(키 없음·미승인·무효)는 종료 코드 3 → 워크플로가 경고만 남기고 배포를 건너뛴다(기존 사이트 유지). 실제 호출인데 서비스가 1,000건 미만이면 빈 사이트 배포를 막으려고 실패 처리.

## 데이터
행정안전부_대한민국 공공서비스(혜택) 정보 — https://www.data.go.kr/data/15113968/openapi.do
(스웨거: https://infuser.odcloud.kr/api/stages/44436/api-docs)

| 엔드포인트 | 쓰는 필드 |
|---|---|
| `GET api.odcloud.kr/api/gov24/v3/serviceList?page&perPage&serviceKey` | 서비스ID, 서비스명, 서비스목적요약, 지원유형, 지원대상, 선정기준, 지원내용, 신청방법, 신청기한, 상세조회URL, 소관기관명, 부서명, 소관기관유형, 사용자구분, 서비스분야, 접수기관, 전화문의, 조회수, 등록일시, 수정일시 |
| `GET .../serviceDetail` | 서비스목적, 구비서류, 공무원확인구비서류, 본인확인필요구비서류, 접수기관명, 문의처, 온라인신청사이트URL, 법령, 자치법규, 행정규칙 (+목록과 같은 필드는 상세 우선) |
| `GET .../supportConditions` | JA0110/JA0111(나이), JA0201~0205(중위소득 구간), JA0301~0303(임신·출산), JA0327(구직), JA0328(장애), JA0329(보훈), JA0401~0403, JA0313~0316, JA0317~0320, JA1101~1103 |

세 엔드포인트 모두 조건 없이 `perPage=1000`(env `PER_PAGE`)으로 전부 순회 → 하루 수십 회 호출(개발계정 일 10,000회).

- 지역: API에 지역 필드가 없어 `소관기관명` 앞머리(시도명)로 시도·시군구를 나눈다. 중앙부처·공공기관은 전국.
- 색인: 지원대상+선정기준+지원내용 글자 40자 이상이고 지원내용 10자 이상인 서비스만 색인, 나머지 noindex. 색인할 서비스가 없는 목록 페이지도 noindex.
- 사이트맵: 5,000개 넘으면 `sitemap-N.xml` + `sitemap.xml`(색인). lastmod는 페이지별 **내용 해시가 바뀐 날**(기준 시각·D-day 글자는 빼고 해시). 기록은 `state/pages.json`(`{경로: [해시, 날짜]}`) — 워크플로의 `after-deploy` 잡이 배포 성공 뒤 main에 `[skip ci]`로 커밋해 다음 실행이 이어 쓴다. 로컬 실제 호출 빌드도 이 파일을 고치므로 커밋하지 말 것(`git checkout state/`).
- 제목: 지자체 서비스는 `${시군구 또는 시도} ${서비스명} 신청 방법·대상·금액 (연도)`, 이름에 지역이 이미 있으면 그대로. 그래도 겹치면 `(소관기관명)` → `(소관기관명 부서명)`을 덧붙여 제목 중복 0 유지(`svcNames`).
- 서비스 페이지: 3줄 요약(대상·지원 내용·신청 기한 D-day), 같은 지역·분야 최근 등록 5개, 같은 서비스명의 다른 지역 링크.
- IndexNow: 키 파일 `/e386846d4b6f939fd1b440af9728c599.txt`. 빌드가 오늘 lastmod가 바뀐 색인 URL을 `indexnow.json`에 쓰고(0개·1만 개 초과면 빈 목록, 기록이 없는 첫 실행은 허브 먼저 1만 개까지), `after-deploy`가 네이버 서치어드바이저·api.indexnow.org로 보낸다.
- `rss.xml`: 최근 등록 색인 서비스 50개(네이버 서치어드바이저 RSS 제출용). `/about.html`: 운영 목적·출처·면책. `og.png`: 1200×630 공유 이미지.
- 대상: `targets.js` 한 곳에 대상 21개(가족·출산 / 나이·상황 / 사업자)의 판정 규칙을 둔다 → 홈 버튼, `/t/<대상>/` 랜딩(3건 미만이면 noindex), 서비스 페이지 칩, 검색 색인. 지원조건 코드는 대부분 서비스가 전부 Y로 찍어 두므로 "묶음에서 Y가 몇 개 안 될 때만" 신호로 쓰고, 나머지는 서비스명·지원대상·선정기준 키워드(제외 문구·나열형 가드 포함).
